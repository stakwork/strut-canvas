# Brainstorm Framing

Check the level of the person's question before you write the tree. A person often brings one solution as if it were the goal. A good brainstorm shows what the person did not consider, not only more of what they asked for.

Do this on the first turn. On a later turn, do it again only when the person changes the topic.

## 1. Find the goal

- Ask "what is this for?" about the person's text. Go up one level at a time.
- Stop at the first goal that the person or the organisation owns. Do not go higher. "Grow the company" is too high.
- Example: "convert PII before we send data to a public model" serves "use public models without leaking sensitive data".

## 2. Infer the goal from the graph first

Look for the goal in this order:

1. The card passed as `about`, and the initiative it is in.
2. What the graph says about the company's direction, and the live initiatives.
3. Earlier brainstorms on the same topic.

Name the node that the goal came from.

## 3. Confirm with the person when the graph does not settle it

- Ask when no node states the goal, or when two goals fit equally well.
- Ask one short question. Offer the inferred goal and one alternative.
- If the run cannot wait for an answer, write the tree under the inferred goal. Mark the root as assumed. Put the question first in the reply.
- Do not ask when the person already stated the goal, or said that the frame is decided.

## 4. Root the tree at the goal

- The root is the goal, not the person's solution.
- Under the root, write a sub-question for the approach. The person's solution is one option there, with `made_by: user`. Add sibling approaches that reach the same goal.
- Do not drop or demote the person's branch. The person can still expand it.

## 5. Surface assumptions

- List what the text takes for granted: scope, threat, constraint, or a required tool.
- When an assumption would change which option wins, write it as a sub-question under the root.
- Example: "Is only PII sensitive?" and "Who must not see the data?"

## 6. Check what already exists

- Look for existing products, open-source tools, standards, and methods that reach the goal.
- Use an outside search when the run has one. If it does not, say in the reply that this search was not done.
- Name existing solutions in the option text, so the person does not rebuild them.
